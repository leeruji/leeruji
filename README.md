### 소개

[Digginn](https://github.com/Digginn)에서 프로덕트 디자인을 맡고 있습니다.
화면을 그리는 데서 멈추지 않고 AI(Claude Code)와 함께 실제로 돌아가는 앱을 직접 고쳐 봅니다.
코드를 처음부터 쓰기보다는, 무엇을 왜 바꿀지 정하고 결과를 눈으로 확인하는 일을 합니다.

### 일하는 방식

- **문제를 먼저 꺼내고 결정까지 끌고 갑니다.**\
  위시버킷 서비스 종료 소식을 보고 대체 앱을 팀에 제안한 것이 Diggin의 시작이었습니다. 개발 일정이 빠듯해지자 개발팀과 디자인팀 음성 회의를 열었습니다. 그 자리에서 '나의 소장템' 칩은 출시 이후로 미루고 폴더 목록 맨 위에 고정한 뒤 구분선을 두는 방식으로 MVP 범위를 정리했습니다.

- **기능을 늘리기보다 줄일 근거를 찾습니다.**\
  같은 링크는 한 번만 저장되는 정책이라면 '상품 복사' 기능 없이 폴더 선택 하나로 해결된다고 제안했습니다. 1:1 문의 실패 안내도 새 토스트를 만들지 않고 기존 공통 메시지를 다시 쓰자고 제안했습니다.

- **말이 앞뒤가 맞는지 끝까지 따집니다.**\
  위시 레벨 5단계 이름을 정하다가, 저장한 상품에 '관심 없음'이 붙는 모순을 짚었습니다. '살까 말까'와 '마음에 듦'은 서로 다른 축이라 순서가 서지 않는다는 점도 짚어 한 단어를 기준으로 강도만 바꾸는 방식으로 정리했습니다. UX 라이팅의 띄어쓰기·온점·말투·용어 기준도 동료 디자이너와 직접 합의해 문서로 남겼습니다.

- **결정의 근거를 남깁니다.**\
  기능명세서 변경이력에는 누가 제안하고 누가 동의했는지, 어느 논의 스레드에서 정했는지까지 적고 링크를 겁니다. 팀에서 답이 빠진 질문은 따로 모아 PM에게 한 번에 확인받습니다.

- **AI는 손을 빌리는 도구로 씁니다.**\
  반복되는 문서·화면 정리는 팀 규칙을 지시서로 만들어 맡깁니다. 다만 시트를 고치기 전에 변경 전·후를 먼저 보고 팀에 올라가는 코멘트는 직접 확인합니다. AI가 근거 없이 문구를 바꾸면 이유를 묻고 PM 확인 전까지 원래대로 되돌립니다.

**[Diggin](https://diggin-landing.vercel.app)**
여러 쇼핑몰에 흩어진 관심 상품을 한곳에 모아 보는 아카이빙 앱입니다. [Digginn](https://github.com/Digginn) 팀에서 프로덕트 디자인을 맡고 있으며 iOS 앱 출시를 준비 중입니다.
팀 결정 사항을 기능명세서와 피그마 화면에 반영하는 반복 작업은 AI 에이전트가 팀 규칙대로 처리하도록 설계했습니다. [AI 협업 워크플로우 사례 보기](https://leeruji.github.io/work/diggin-ai-workflow/)
